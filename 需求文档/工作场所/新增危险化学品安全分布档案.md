## 一、你的方案优势分析

### 1. **符合业务实际流程**
```
危险化学品台账(基础数据层)
    ↓ 自动判定
重大危险源判定(规则计算层)
    ↓ 筛选回显
重大危险源管理模块(管理监督层)
```
这个流程链路清晰,避免了数据重复维护。

### 2. **解决了重复录入问题**
- 当前设计:危化品台账和重大危险源是两套独立系统
- 你的方案:危化品台账是**唯一数据源**,重大危险源只是"符合条件的视图"

### 3. **"危险化学品安全风险分布档案"的必要性**
这个模块确实是GB18218标准的核心要求:
- **按区域/单元聚合**:同一储存区域内多种化学品的临界量累加
- **动态判定**:当某区域化学品库存变化时,自动重新计算是否构成重大危险源
- **分布可视化**:企业需要清楚知道哪些区域是重大危险源

### 4. **区域分类标准**
系统将所有区域分为两大类：
- **重大危险源区域 (R≥10)**：需要重点监管的区域，内部细分为：
  - 一级重大危险源：R≥100
  - 二级重大危险源：100>R≥50
  - 三级重大危险源：50>R≥10
  - 四级重大危险源：10≤R<50
- **非重大危险源区域 (R<10)**：包括有危化品但未达临界量的区域，以及无危化品的安全区域

## 二、需要明确的关键问题

### 问题1:判定逻辑放在哪里?
根据你的描述和GB18218标准,我建议:

| 判定类型 | 放置位置 | 原因 |
|---------|---------|------|
| **单品种判定** | 危化品台账模块 | 单个化学品的最大库存 ÷ 临界量,简单计算 |
| **多品种累加判定** | 风险分布档案模块 | 需要按"生产单元/储存单元"聚合多个化学品 |
| **最终判定结果** | 重大危险源模块 | 只读展示,不承载判定逻辑 |

**关键点**:你提到的"在危化品模块内判定"是对的,但需要区分:
- 危化品台账:**记录单品种数据** + 标记"是否可能构成重大危险源"
- 风险分布档案:**按区域聚合** + 执行GB18218的多品种累加公式
- 重大危险源模块:**回显已判定的结果** + 承载包保/监测/备案等管理职能

## 三、"危险化学品安全风险分布档案"模块设计建议

### 核心能力
```
【新增菜单】危险化学品安全风险分布档案
  ├─ 按区域/单元维度组织
  ├─ 自动从危化品台账拉取数据
  ├─ 执行GB18218判定规则(单品种 + 多品种累加)
  ├─ 生成判定结果:是否构成重大危险源
  └─ 输出结果到"重大危险源管理模块"
```

### 与现有模块的关系
```
危化品台账(数据源)
    ↓ 提供基础数据
风险分布档案(判定引擎)
    ↓ 生成判定结果
重大危险源管理(业务管理)
```

### 典型场景举例
> **场景**:某企业在"危化仓A-01区"储存了3种化学品:
> - 乙醇 500kg(临界量500kg)
> - 甲醇 300kg(临界量500kg)
> - 丙酮 200kg(临界量500kg)

**判定过程**:
1. 危化品台账:分别记录3条数据,单品种判定均为"<临界量"
2. 风险分布档案:自动聚合该区域数据,计算 `500/500 + 300/500 + 200/500 = 2.0 ≥ 1`,判定为"重大危险源"
3. 重大危险源模块:回显该区域为重大危险源,触发包保、监测、备案等流程

## 四、潜在风险提示

### 1. **数据一致性问题**
- 危化品台账修改库存后,风险分布档案需要**实时/定时重新计算**
- 建议:触发机制(保存时自动计算)+ 定时任务(每日凌晨全量重算)

### 2. **区域/单元的定义**
- 你的设计文档中"所属单元"字段需要与风险分布档案的"区域"字段关联
- 建议:建立统一的"储存单元字典表",两个模块共用

### 3. **历史数据追溯**
- 重大危险源判定结果应保留历史版本(何时判定、依据哪些化学品)
- 建议:风险分布档案保留快照记录

### 4. **用户权限**
- 技术负责人:可在危化品台账新增/编辑,触发重新判定
- 安全管理机构:查看风险分布档案,提交备案
- 主要负责人:审批备案,查看汇总报表
